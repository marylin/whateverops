The error states are a design strength — they show real care. The healthy-state panels feel more generic. The status page is clean and effective. The mobile experience is good.

## Findings (by impact)

### HIGH IMPACT

#### FINDING-001: Touch targets too small — all buttons at 28px [Accessibility]

All interactive elements (Retry, Status, Status page, Refresh) render at 28px height. WCAG 2.2 Success Criterion 2.5.8 requires 44px minimum for touch targets. On the mobile view, these are difficult to tap accurately.

**Fix:** Increase padding on all buttons and links in the header and panel cards to achieve 44px minimum height. `py-2.5` or `min-h-[44px]` on all clickable elements.

**Effort:** S (CC: ~10min)

---

#### FINDING-002: Heading hierarchy weak — H1 at 18px, H3 at 14px, H2 skipped [Typography]

Page title "WhateverOPS" at 18px barely reads as a heading. Panel titles at 14px are nearly indistinguishable from body text. H2 level is skipped entirely (H1 → H3). This weakens the visual hierarchy — the eye doesn't know what's important.

**Fix:** Bump H1 to 24px, bump H3 panel titles to 16px. Consider adding an H2 for section groupings if panels are ever categorized.

**Effort:** S (CC: ~5min)

---

#### FINDING-003: Raw ISO timestamps shown to users [Content Quality]

Multiple panels display raw ISO 8601 timestamps:

- Vercel: "Last Deploy Time: 2026-03-18T04:38:24.363Z"
- WhateverOPS: "Last Checked: 2026-03-18T10:01:13.916Z"

These are developer debug output, not user-facing content. Self-hosters will see these daily.

**Fix:** Format timestamps as relative ("2h ago") or human-readable ("Mar 18, 4:38 AM"). The `Intl.RelativeTimeFormat` API or a lightweight library handles this.

**Effort:** S (CC: ~15min)

---

### MEDIUM IMPACT

#### FINDING-004: Vercel deploy IDs are unreadable truncated hashes [Content Quality]

The "Recent Deploys" section in the Vercel panel shows:

```
dpl_A7euGirQ1QSBTLyk9Wv24yNXMdwV - bachuwa-ai-crm-f - R...
```

Deploy IDs are meaningless to users. The project name is truncated. This wastes the most valuable real estate in the panel.

**Fix:** Show project name first, status badge, and relative time. Truncate or hide the deploy ID entirely.

**Effort:** S (CC: ~10min)

---

#### FINDING-005: "Cached" badge and staleness dot are redundant [Visual Noise]

Every healthy panel shows both a "cached" text badge AND a green staleness dot, plus an "Xs ago" timestamp. Three indicators for the same concept (data freshness) compete for attention.

**Fix:** Remove the "cached" text badge. The green dot + timestamp are sufficient. Or: merge into a single indicator: green dot with tooltip showing "Cached 15s ago".

**Effort:** S (CC: ~5min)

---

#### FINDING-006: Error panel layout inconsistency [Visual Consistency]

Error panels vary in layout:

- Railway: Error message only, no hint text
- Supabase: Error + specific hint ("check SUPABASE_MANAGEMENT_KEY")
- Supabase Auth: Error only, shorter layout
- Neon: Error + hint ("verify NEON_API_KEY format")

Some errors have hints, some don't. Some have "Last success: 0s ago", some show it differently. Error panels should follow one consistent template.

**Fix:** Standardize: all error panels show [error message] + [hint if available] + [last success time] + [Retry | Status page]. Same layout regardless of integration.

**Effort:** S (CC: ~10min)

---

#### FINDING-007: Metric label inconsistencies [Content Quality]

- "Api Key Count" — should be "API Key Count" (proper abbreviation casing)
- "Key Valid: Yes" — should be a status badge, not text
- "Open P Rs" — appears to be "Open PRs" with a rendering issue
- "Response Time Ms" — should be "Response Time" with "ms" as the unit suffix

**Fix:** Audit all `parsePanel()` output field names for consistent casing and formatting. Use abbreviation rules: API, PR, MRR are always uppercase.

**Effort:** S (CC: ~10min)

---

#### FINDING-008: Footer text "11 of 15" is wrong and nearly invisible [Bug + Contrast]

The footer shows "11 of 15 integrations configured" — but there are 16 integrations now (eng review BUG-1). The text is also extremely faint gray on the dark background, barely meeting contrast requirements.

**Fix:** Already tracked as eng review action item #2 (fix to `results.length`). Additionally bump footer text from gray-600/700 to gray-400 for readability.

**Effort:** S (CC: ~2min, bundled with eng fix)

### POLISH

#### FINDING-009: No page title differentiation [SEO/UX]

Both `/` and `/status` use `<title>WhateverOPS</title>`. When multiple tabs are open, users can't distinguish them.

**Fix:** Status page should set `document.title = 'Status | WhateverOPS'` in a `useEffect`.

**Effort:** S (CC: ~2min)

---

#### FINDING-010: Status page footer text at 10px [Typography]

`text-[10px]` is below the 12px minimum for readable text. The "Last refresh" and "Auto-refreshes every 30s" footer is designed to be subtle but crosses into unreadable.

**Fix:** Bump to `text-xs` (12px).

**Effort:** S (CC: ~1min)

---

#### FINDING-011: Purple primary accent — AI slop signal [AI Slop]

The primary accent `#7C3AED` (violet) is the single most common color choice in AI-generated web interfaces. It's not wrong — it works well on dark backgrounds — but it immediately signals "template" to designers and discerning developers.

For OSS credibility, this is worth noting. The target audience (solo dev-founders) has seen hundreds of purple AI dashboards. A distinctive accent (teal, amber, or a specific branded color) would differentiate.

**Fix:** Defer to a design consultation. This is a branding decision, not a bug. If changing: update the accent in Tailwind config (`theme.extend.colors`) — one file, all references update automatically.

**Effort:** S (CC: ~5min for the swap, but needs design decision first)

---

#### FINDING-012: No favicon [Polish]

Browser tab shows the default Vite favicon. For OSS launch, a simple "W" or ops-themed icon gives a professional impression.

**Fix:** Add a favicon to `frontend/public/`. Even a simple SVG letter mark works.

**Effort:** S (CC: ~5min)
