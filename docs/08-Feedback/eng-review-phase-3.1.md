## Section 1: Architecture Review — 3 issues found

### ISSUE 1: DRY violation — status.ts duplicates dashboard.ts config logic [HIGH]

**Problem:** `status.ts` (180 lines) copies ~120 lines of integration config assembly from `dashboard.ts`. Same 16 imports, same env var reads, same config objects.

**Risk:** Adding a 17th integration requires updating both files in lockstep. Guaranteed drift bugs.

**Decision:** ✅ Extract shared `integration-registry.ts`. Both routes call it.

```
  BEFORE:                              AFTER:
  dashboard.ts (194 lines)             integration-registry.ts (shared)
    └─ 120 lines config logic            └─ buildConfiguredIntegrations()
  status.ts (180 lines)                dashboard.ts (~30 lines)
    └─ 120 lines config logic (copy)     └─ calls registry, returns full panels
                                        status.ts (~30 lines)
                                          └─ calls registry, returns health only
```

### ISSUE 2: Status endpoint triggers full API fetches (public, unauthenticated) [MEDIUM]

**Problem:** `/api/status` is public. Each request runs `runIntegration()` for all 16 integrations. If cache is cold (restart, TTL expiry), this triggers 16 real upstream API calls.

**Mitigated by:** Cache layer (60-300s TTLs). Most requests hit cache. First request after startup is the risk window.

**Decision:** Acceptable with rate limiting (see ISSUE below). Cache makes this efficient in practice.

### ISSUE 3: Self-monitoring creates self-referential HTTP call [LOW]

**Problem:** Self-monitoring integration fetches its own `/health` endpoint via HTTP. During high load, this request competes for the same resources it's monitoring.

**Mitigated by:** `/health` is a trivial endpoint (JSON response, no DB/API calls). The self-call adds negligible overhead.

**Decision:** Accept. This is the standard pattern for self-monitoring. The alternative (internal health check without HTTP) would break the integration contract pattern.

**Problem:** `.github/workflows/ci.yml` triggers on `branches: [main, staging]` but the default branch is `master`. CI doesn't run on PRs to `master` or pushes to `master`.

**Decision:** ✅ Fix. Change CI to `branches: [master, staging]`.
