## Blocking Gaps (must fix before OSS launch)

### GAP-1: No Rate Limiting on API Endpoints [CRITICAL]

**What:** Backend has zero rate limiting. All 3 API routes (`/api/dashboard`, `/api/status`, `/api/webhooks/n8n/:event`) accept unlimited requests.

**Why this blocks OSS launch:** Once the repo is public, anyone can deploy and configure it. A misconfigured instance or malicious actor can send unlimited requests through the proxy, which then hit upstream APIs (Stripe, GitHub, Vercel, etc.) using the user's API keys. This could:

- Exhaust API rate limits on user's Stripe/GitHub/Vercel accounts
- Generate unexpected costs on metered APIs (Anthropic, OpenAI)
- Create a denial-of-service on the backend

**Fix:** Add Hono rate limiting middleware. Per-IP limits on `/api/dashboard` (e.g., 60 req/min) and `/api/status` (120 req/min). Use `hono/rate-limit` or a lightweight middleware.

**Effort:** S (human: ~2hr / CC: ~10min)

---

### GAP-2: No React Error Boundary [CRITICAL]

**What:** No `ErrorBoundary` component wraps the dashboard panels. If any single panel component throws a runtime error (bad data shape, null reference, etc.), the entire React app crashes to a white screen.

**Why this blocks OSS launch:** BR-2.8 requires "graceful degradation." Backend graceful degradation is solid (per-integration error isolation), but frontend has zero protection. With 15 different integrations returning different data shapes, a single unexpected field from any upstream API will crash the entire dashboard. Self-hosters with partial configs will hit this.

**Fix:** Add React `ErrorBoundary` component wrapping each panel individually. On error: show panel-level error state ("This panel encountered an error — click to retry") instead of crashing the app. Also add a top-level boundary for the entire app.

**Effort:** S (human: ~2hr / CC: ~10min)

## Hardening Gaps (should fix for quality OSS launch)

### GAP-6: Integration Tests Not in CI Pipeline [MEDIUM]

**What:** `tests/integration/cache/cache.test.ts` and `tests/integration/webhooks/webhooks.test.ts` exist but CI only runs `bun test tests/unit/`. Integration tests are silently skipped.

**Fix:** Add `bun test tests/integration/` step to CI after unit tests.

**Effort:** S (CC: ~5min)

---

### GAP-7: No Security Headers [MEDIUM]

**What:** Backend serves API responses without security headers (CSP, X-Frame-Options, X-Content-Type-Options, Strict-Transport-Security). CORS is properly scoped but other headers are missing.

**Why:** OWASP best practice for any public-facing API. Self-hosters deploying to the public internet need these defaults.

**Fix:** Add `hono/secure-headers` middleware in `backend/src/index.ts`.

**Effort:** S (CC: ~5min)

---

### GAP-8: No 404 Route in Frontend [LOW]

**What:** `App.tsx` has routes for `/` and `/status` only. Any other path renders a blank page.

**Fix:** Add a catch-all `<Route path="*" element={<NotFound />} />` that redirects to `/` or shows a helpful 404 page.

**Effort:** S (CC: ~5min)

---

### GAP-9: Status Page Subdomain [LOW]

**What:** BR-3.16 specifies "Status visible on a public status page at status.whateverops.io" but the status page is at `/status` (internal route). No separate subdomain configured.

**Why:** For self-hosters, `/status` is fine. For the hosted version (Phase 4+), a subdomain is expected. Not blocking for OSS launch but noted for completeness.

**Fix:** Defer to Phase 4. Document the `/status` route as the current status page in README.

---

### ~~GAP-10: n8n Workflows E2E Verification~~ [DEFERRED]

Postponed by decision. n8n is for documenting the process — deferred to next phase after documentation is updated.

---

### GAP-11: No Circuit Breaker for Failing Integrations [LOW]

**What:** If an upstream API is down, the retry logic (`backend/src/lib/retry.ts`) retries with exponential backoff on every refresh cycle. There's no circuit breaker to fast-fail after N consecutive failures.

**Why:** With 15 integrations refreshing every 60s, a single down API generates 3 retry attempts × every refresh = significant wasted requests. A circuit breaker would skip fetches for known-down integrations and probe periodically instead.

**Fix:** Defer to Phase 4. Current retry behavior is acceptable for personal use and small-scale OSS.
